# Read this to understand the backend

### Install Dependencies

Run 'npm install' command in a terminal within the backend folder


### Configure Environment Variables

Create a .env file with data that corresponds to your SQL stuff:

DB_HOST=localhost
DB_USER=root
DB_PASSWORD=password
DB_NAME=occuvision

PORT=3000


### Start Server

Run 'node server.js' in the same terminal

Server runs at:

http://localhost:3000

## *currently only rooms has GET and POST functionality*

### Room

Represents a physical room being monitored.

| Field | Type |
|---------|---------|
| room_id | Integer |
| room_name | String |
| capacity_limit | Integer |
| occupancy_threshold | Integer |

### Camera

Represents a camera assigned to a room.

| Field | Type |
|---------|---------|
| camera_id | Integer |
| camera_name | String |
| ip_address | String |
| status | String |
| assigned_room_id | Integer |

### Occupancy Log

Stores occupancy data over time.

| Field | Type |
|---------|---------|
| log_id | Integer |
| room_id | Integer |
| occupancy_count | Integer |
| recorded_at | DateTime |

## RTSP camera management

### Database migration

For an existing database, apply `backend/database/migrations/20261101_add_camera_connection_state.sql` once (for example, import it in phpMyAdmin with the `occuvision` database selected). This migration adds `desired_connection_state`, defaulting existing cameras to `disconnected`.

Do not run `npm run db:init` to apply this migration to an existing database: `backend/database/schema.sql` drops and recreates the database. A fresh database created from that schema already includes the new column.

### Configure the camera service token

Set the same private token in `backend/.env` and in the Python service environment:

```env
CAMERA_SERVICE_TOKEN=<a-long-random-secret>
```

Keep this token out of source control and logs. The backend's ordinary camera APIs redact credentials; only the token-protected Python configuration API returns full RTSP URLs.


In the Python terminal, enter the same token configured in `backend/.env` without placing it in a command or source file:

```powershell
$secureToken = Read-Host "Camera service token" -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureToken)
try {
  $env:CAMERA_SERVICE_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
}
$env:OCCUVISION_API_URL = "http://localhost:3000/api"
python .\main.py
```

The detector reconnects cameras that remain desired-connected after a Python service restart. Startup clears their `last_communication`, so their actual data status stays offline until a new occupancy count is accepted. Processing defaults to one inference every 10 seconds; set `FRAME_INTERVAL_SECONDS` to change it. The manager checks desired state every 2 seconds; set `CAMERA_POLL_INTERVAL_SECONDS` to change that interval.

### Add and connect a camera

In the Vue app, open **Cameras**, add a camera name, assign a room, and enter its `rtsp://` URL. Camera IDs are generated by the database. Click **Connect** for that camera. The button reports the requested connection state separately from actual online/offline data status. To replace an RTSP URL while editing, enter a new URL; leave the field blank to preserve the saved URL. The displayed URL has its credentials redacted.

The Python process reconciles the persisted desired state when it starts and polls for changes every 2 seconds. Cameras without a room or valid RTSP URL cannot be connected. Occupancy counts are sent to `POST /api/occupancy`; frame images are not saved.

OpenCV's RTSP open/read timeout parameters are used when supported by the installed OpenCV backend. If the build rejects those parameters, the service falls back to OpenCV defaults; shutdown may then wait for a blocked capture read to return. Shutdown also waits for an in-flight inference to finish. Test against the actual camera/OpenCV build before relying on bounded shutdown time.
